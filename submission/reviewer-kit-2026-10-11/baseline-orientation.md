The question is narrow: **does the interface help this convenience sample locate a named reference vessel and retrieve its displayed model output?** This is not a patient-specific anatomy test, diagnosis exercise, or clinical-utility trial.

Prepare two genuine baseline panels from the exact reviewed build, one for UCI411-171 and one for UCI411-276, full inputs and the training-selected rule. The static condition shows this fixed overview with no camera or selection controls. The interactive condition is the actual app at the matching overview. Do not invent an anatomical sketch, substitute a promotional image, hide disclaimer text, or give either condition extra labels or explanatory prose.

Before enrolling anyone, save the captures, hashes, exact viewport/camera/state, and answer regions verified against named source mesh selection. Lock a new optional-baseline protocol with those assets and regions. If a name overlaps another vessel or a screenshot cannot define an unambiguous answer region, repair the display before freezing. **A textual artery table cannot substitute for a spatial orientation baseline.** Until this freeze exists, do not run or score this comparison.

Give the same prompt in each condition, with the allocated vessel substituted:

> Locate [LAD or LCX] on this reference anatomy and report its displayed full-input probability. Show where you found the named vessel. Say “done” when you have your final answer.

Measure from prompt completion to first final answer, cap 90 seconds. Static-condition pointing is accepted only within its frozen answer region; interactive selection is accepted only when the matching named target is selected. Record name location, correct probability, elapsed time, assistance, and a free-form statement about what the reference anatomy represents. Do not coach or give correctness feedback between conditions. Do not score medical territories, plaque location, or clinical action.
